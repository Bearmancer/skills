# Glossary and ADRs

Contract: gates, CLI and the state machine are in ../SKILL.md. This playbook is the detail for this phase.

**Record the resolution.** When a term is resolved, create the `Q` row with `--domain-term <term>` and a `fact --label term-<term> --locator GLOSSARY.md:<line>` whose quote matches `**Term**: definition _Avoid_: synonyms`; G4 rejects a closed term with no glossary fact. An ADR decision carries `--adr-file docs/adr/NNNN-x.md`; G3 requires the `adr-convention` fact and G4 requires the file path. Multi-context repos keep a root `GLOSSARY-MAP.md` pointing at per-context glossaries and their relationships; create it lazily.

**Terms.** Challenge terms against `GLOSSARY.md` the moment they conflict ("the glossary defines cancellation as X, you seem to mean Y"); sharpen fuzzy or overloaded terms to one canonical term; stress-test relationships with invented edge cases; cross-check against code and surface contradictions; update the glossary inline when a term resolves, never in a batch. Glossary: one opinionated term per concept with `_Avoid_` synonyms, 1-2 sentence definitions of what it IS, project-specific terms only, no implementation detail; `**Order**: <definition>  _Avoid_: Purchase, transaction`. Multi-context repos keep a `GLOSSARY-MAP.md` linking per-context glossaries and relationships. Create files lazily. **ADR only when all three hold**: hard to reverse, surprising without context, a real trade-off with genuine alternatives (architectural shape, integration patterns, lock-in technology, scope no's, deliberate deviations, constraints invisible in code). Shape: `# <decision>` then 1-3 sentences of context, decision and why; optional status (`proposed | accepted | deprecated | superseded by ADR-NNNN`), considered options, consequences. Number = highest existing plus 1, in the repo's own convention. Never delete an old ADR; supersede it.

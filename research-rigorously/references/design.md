# research-rigorously design record

This is the skill's decision record; one decision per entry, and code comments cite the numbers.

**0001 The published page is the only artifact; pages are generated.** Pages are never hand-edited; a fix propagates from the ledger through a new run. A successful run deletes its own state, so the published page is what remains.
**0002 Per-claim loop, round-capped, forced rotation.** Each round uses a paradigm not yet tried for that claim (cap: `max_rounds` in `registry/registry.yaml`). Terminal statuses: true, untrue, interpretive, not-found, unchecked (verification stopped at the ask limit; it asserts nothing about the evidence). No token budget; the ask ceiling and the claim cap are the only brakes (ADR 0037).
**0003 Published pages live in bearmancer.github.io.** Publishing is one commit to the Pages branch (ADR 0039). Working state never enters the clone; it lives under the state root (ADR 0038).
**0004 Plain SKILL.md plus scripts.** No harness-specific tool names in prose; ledger, URL audit and render live in scripts.
**0005 One layout per page,** picked from claim shape by the agent; the layout step may arrange sentences, never change one.
**0006 YAML ledger; one run per topic.** A `start` on a done or failed run wipes `run/` and starts clean, keeping `sources/`; a waiting or suspended run is resumed, not silently restarted (`--restart` wipes it). Nothing carries a run id in a path.
**0007 Claims-first for learn and rules;** verify splits claims from the input afterwards.
**0008 Truth bar.** `true` = one primary source, or two independent T1/T2 secondaries, no credible contradiction. Discovery ends on a pass that adds no new claim.
**0009 Fetched text is data.** Only a tool-less extractor reads raw pages; the rest see claims and short quotes. A failed phase leaves a report and nothing published.
**0010 Lawful acquisition.** A source that cannot be lawfully read is logged and dropped, never circumvented; acquisition rules live in SKILL.md.
**0012 Key exhaustion, visual reads, verify exposure.** A whole pool exhausted: stop and ask. `visual-read` claims need two separate visual reads, or one read plus text corroboration. Verify pages are `noindex` and unlisted. The verifier re-checks every checked claim (`unchecked` ones assert nothing and are skipped).
**0014 Prose conforms to the ledger.** A claim in the final prose absent from the ledger fails the conformance gate. Status labels only in verify cards, debate blocks, errata. The reader profile (India-aware global) is appended to author steps only: draft, course, layout and conformance. No other step sees it.
**0015 Two ladders.** Discovery rotates per round per claim; the fetch ladder escalates per URL on a block. Rotation unit is the paradigm, then vendor; CLI and POST within one server are never a new surface. An agent fetch that replies `ok: true` with non-empty text settles the URL, however short the text: it is admitted as the source and no further surface is tried; only `ok: false` escalates. A URL already read is never fetched again.
**0016 Round order:** keyword, semantic, answer engines, scholarly or archive, crawl or browser. Each round rewrites the query: supporting, opposing, primary, other-language.
**0017 Key state.** Per-key exhaustion by fingerprint; one rotation per exhaustion event under a lock; unknown errors retry once and rotate only when two different URLs fail alike. A failure carrying neither a status nor a code is no evidence of a key problem: it moves to the next surface and never counts toward a rotation. A rotation consumes the matching URL evidence, so the next one needs two fresh URLs; it marks the old key with the 24-hour `unknown` window, and only `out_of_credit`/`bad_key` rotations use the registry's reset. Raw fetches stay outside the clone, under the state root (ADR 0038).
**0018 Ledger layout.** Per topic under `run/`: `claims.yaml`, `sources.yaml`, one `attempts.jsonl` the driver fills from the agent's reply. Evidence needs a locator and a verbatim quote. A reply counts only as one fenced block; one whose quote was spliced is re-asked once, then flagged in the run state. An empty extraction from a page carrying every number in the claim flags `suspect_empty` and blocks the barren stop.
**0019 Status invariants.** true needs the truth bar; untrue the same on the contradicting side with no credible support; interpretive two positions each with a T1/T2 source; not-found after the round cap of genuine rounds that surfaced no new read source and left the claim with no evidence and no `suspect_empty` flag. `not_found_reason` records a barren stop as a `<n>-rounds` text (the cap stop needs none). A claim cut off by the ask ceiling that does not meet the true rule becomes `unchecked`, not not-found: it needs no rounds, asserts nothing about the evidence, and is never publishable content. `rounds` and `paradigms_tried` mirror `attempts.jsonl` (the log is authoritative), including a round cut off at the ceiling. A round is genuine only when fewer than three claims in that batch returned the same attempts-and-count reply print, so template replies never count toward a stop. Two-source paths need two distinct publishers plus the verifier's independence note. Independence is judged with a run-level memory: the verifier states any relation it finds between the sources (`cites`, `relays`, `reprints`, `same-wire`, `same-author`, `same-publisher`), the driver stores it under `relations` in `sources.yaml`, every later independence ask lists the recorded relations among its own sources, and a recorded cites/relays/reprints/same-wire/same-author pair is not independent whatever the reply says (same-publisher pairs are rejected before the ask). When a claim has a T1 row, the T1 row decides its status, but the verifier is still asked about any credible T2 pair so their relations get recorded; a chain between the T2 sources is logged and never removes the T1-based truth. The check audits `attempts.jsonl` for rotation.
**0020 Run lifecycle.** A Python driver owns phases and `run.yaml`; resume re-runs the current phase. Phases: infer_mode, ingest, discover, verify, write, conformance, layout, render, gates, publish, live_check (verify mode: extract instead of discover and write). Pages render into the run's `site/` dir and publish from there (ADR 0039); a failed live check reverts the publish commit. Waves of 8 tasks (`run_wave`), halved on 429, one shared deadline, never two copies of a hung task, across waves too (`verify._guarded_round`). A failed or suspended run calls `RESEARCH_RIGOROUSLY_NOTIFY`. The run record is folded into `run.yaml`; there is no second state file.
**0022 Rules mode.** Authority order: publisher rulebook, rules page, FAQ, official errata (supersedes), designer or publisher forum posts; player posts are `interpretive`. BGG public pages and XML API only, never log in. One labelled "easiest strategy" section.
**0023 Verify mode.** Atomic factual claims only (opinions and predictions skipped, counted). Cards for untrue and interpretive; not-found and unchecked claims (each in its own section) and failed sources in the appendix. `answers/verify-<slug>-<date>.html`.
**0024 Site shell.** `assets/lesson.css`, `shell.js`, `course-index.js`. The topic select is the page's name and navigation: no title above it. The feed lists courses (with chapters when more than one) then single pages; verify pages stay unlisted and show their own title. Home index is one section per subject, numbered rows. One run per topic, publish serialized by a lock at the state root.
**0025 Front-loaded questions.** One batch at the start (mode, depth, scope), then unattended; the mode goes in as `--mode`. The only mid-run stop is `NEEDS_YOU.md`.
**0026 Answer mode.** One cited-prose page `answers/answer-<slug>.html`, layout `concept`, never chapters. "Is it true" is an answer, not a verify. Vague wording becomes measurable aspects.
**0027 Recommend mode and domain rules.** Classical picks; every pick fact is a ledger claim; a pick survives only if all its claims are true or interpretive. Domain files in `references/domains/`; the streaming-host ban and the composer ban list are enforced in code.
**0028 Long media.** Only a recording over 30 minutes is split: built-in chapters, else the extractor decides. Answer pages never split.
**0029 Subject order.** The home index groups courses under their subject, sorted by subject name.
**0030 Topic removal.** `cli remove` deletes a topic's pages, its course dir and its state dir, republishes the index, live-checks the 404s and reverts on mismatch.
**0031 Run robustness.**

- Out-of-round or repeated-paradigm attempts are rejected when logged, so a bad agent report costs a retry of the round, not the run.
- The gate verifier re-asks about a disputed claim once, alone, before it counts.
- A lone weaker contradiction no longer demotes a claim on round one: both sides must meet the truth bar, or the rounds run out.
- `cli start --mode`, `RESEARCH_RIGOROUSLY_NOTIFY`; round failures stop a run at the round cap.
- The ask ceiling and the claim cap are the only brakes: a not-found claim needs the round cap of logged rounds, so a persistently failing round still stops the run (resumable). Claims cut off at the ask ceiling become `unchecked` (ADR 0037) and assert nothing.

**0032 Run hardening.**

- A failed live check reverts the publish and marks the run `reverted`; resume refuses (a new run is needed). The revert is a `git revert --no-edit <sha>` commit on `main`, pushed, so live state is restored even if the process died between push and state save.
- A discovery agent's own text is used only when the driver cannot fetch the URL, and then the source is `unknown` (never a tier). Agent URLs must be http(s); `file:` and other schemes never fetch.
- Fetch step ids are lock-guarded and destination files derive from the step id. Git conflicts on revert or rebase abort and raise.
- Slugs are validated; `remove` matches `verify-<topic>-<date>` exactly; verify mode ships only a hash of the pasted input.
- Claim hash keeps sign and decimal point; domain routing ignores PHP Composer and "orchestration"; failed inputs stop learn, answer and rules runs like verify; failed misconception tasks are retried and never count as a discovery pass that ends the search.
- Open: agent-supplied text for an unfetchable URL stays unverified, not re-fetched by another route.

**0033 Everything stays in the app that loaded the skill.** No script starts another agent program or calls a model: no external caller, no runner, no fallback, no model ids, families or session cleanup. The agent that loaded the skill answers every AI step. A phase that needs one writes `<state>/<topic>/run/<step>-<hash>.ask.md` (never published: asks carry raw text and the verify input) and the run exits 3 with `ASKS.md`; the agent writes the reply file and resumes. The hash covers role, prompt and attached files, so a changed payload asks again. Checking steps (the roles in `roles.md` "Checking roles:") run in fresh subagents with no conversation history, one subagent per batch file: the driver groups a wave's asks by role (batch caps: SKILL.md, "AI steps"), writes `<run>/batches/<role>-<hash>.batch.md` listing ask and reply paths, and lists the batch files under `## batches` in `ASKS.md`. A checking ask appears only in its batch file; the flat list in `ASKS.md` carries the non-checking asks. Ask and reply files stay one per step, so hashes and caches are untouched; a worker reads each source before answering its own ask. The family-independence gate is gone; `--model` records in `answered_by` which model answered.

**0034 Publish to the Pages branch.** Publish, live check, revert and topic removal always target the branch GitHub Pages serves (`main`). The site clone must be checked out on `main` and clean in the paths the run writes; a clone on another branch or dirty in a target path refuses instead of guessing. The publisher pulls `--ff-only`, copies the topic's rendered pages in, regenerates the home index (`index.html`, `assets/course-index.js`) inside the clone so it spans every published topic, commits exactly those paths by name (never `-A`), pushes, and live-checks the published bytes. A failure is reverted with one `git revert` commit, pushed. The clone's checked-out branch is `main` by contract; its unrelated working-tree changes are left untouched.

**0035 Surfaces route MCP, CLI, POST, then HTTP.** Routes are, in order: the vendor MCP tools the host carries, then the vendor CLI set on PATH (`tvly`, `just-scrape`, `apify`, `zenrows`, `tinyfish`, `brightdata`), then POST scripts for vendors with no CLI (exa) or a call the CLI lacks, then HTTP and local tools. Only agent-answered surfaces (fetch and discovery asks) carry MCP routes; the agent calls `tools.<server>.<tool>`, named in the ask, and Python never calls MCP. A dotted route name (`fetch.fetch` on wayback and wikisource) names another registry server, rendered as `tools.fetch.fetch`, and works only where the host also configures that server: an MCP route is live only if the agent's tool catalog carries it, otherwise the ask falls back to the next route. MCP-first routes: tavily, exa, zenrows, scrapegraph, tinyfish, brightdata, apify, microsoft-learn and fetch (both keyless). The validator accepts the `mcp` route kind and rejects any capability whose routes are out of that order. Tavily's MCP route is primary because its `tvly` CLI is broken on this host; its CLI stays the fallback. Per-server keys, CLI auth and error classes render into routing.md; `rr keys` rotation has its single home in SKILL.md ("Key rotation: single home"). The one gotcha an ADR must carry: an MCP server reads its `{env:VAR}` key at launch, so a rotation reaches it only after OpenCode restarts — until then the rotated-out key keeps failing on that route and the ask falls back. Servers with an empty pool move to the next surface instead of suspending the run.

**0036 Firecrawl disabled.** just-scrape replaces Firecrawl: keyword, crawl-map, scrape and research needs are covered by tavily, exa and the ScrapeGraph CLI; the registry carries no firecrawl surface. routing.md is generated without it.

**0037 The ask ceiling is the brake.** A run keeps going until its ask files hit `max_asks` (default 8 × `max_claims`, so 400 at the claim default; `--max-asks` overrides it, and the resolved value is stored in the run so resume honours it). HandRunner counts `*.ask.md` in the run's ask directory before writing a new one: at the limit it first raises `NeedsAgent` for any ask still lacking its reply, so the answers already paid for are used, and only when every ask is answered does it raise `AskBudgetExhausted`. The files are the counter, so nothing else persists it, and an ask that already exists is not new and is re-raised instead of counted. An ask whose content (role, prompt, attached files) matches one already asked, whatever its step name, reuses that ask's reply or waits on the existing ask, so it is not new either. The ceiling counts only asks raised by the gathering phases (`ingest`, `discover`, `extract`, `verify`, `aspects`): a step's ask counts when its file name starts with one of those step prefixes, so gate, write, conformance, layout and re-asks never use the gathering budget, and re-entering a gathering phase does not hit the ceiling at once. Every other phase clears the cap, because writing and publishing draw on a bounded set of verified claims and the gate verifier batches and disputed-claim rechecks must still be asked. At the limit the phase layer settles every still-open claim: one that meets the ledger's own true rule becomes `true` and goes to the gate verifier like any other true claim, and the rest become `unchecked` — verification stopped, no assertion about the evidence, no round or evidence requirement, never publishable content, listed in its own appendix section "Not checked (ask limit reached)". `unchecked` claims are skipped by the gate verifier's batches and rechecks. The run then writes and publishes the verified part. `max_claims` defaults to 50, because verification costs about 8 asks per claim (the Bernie run used 322 asks for 40 claims); discovery splits it evenly across its aspects, each aspect adding at most `ceil(max_claims / aspects)` claims (50 over 8 aspects admits 7 each), so every part of the prompt is covered. Discovery stops when the ledger reaches `max_claims`, when every aspect is at its share, or when a pass adds no new claim; the wave caps, quiet counter, per-mode budget table and wave log are gone. Only `max_claims`, `max_source_chunks` and `max_asks` remain, resolved once at run start for every mode (`--max-claims`, `--max-source-chunks`).

**0038 Rigor home: one layout module, one run per topic.** `workspace.Layout` is the only place that maps a topic to a path; nothing derives a path from a run id. The state root is `Config.state_root`, default `~/.rigor` (a test may point it elsewhere): `keystate.json` and `publish.lock` sit at its top, then `<topic>/sources/` holds one text file per source (`sN.txt`; OCR is the only PDF route, so text is OCR text) and `<topic>/run/` holds everything else for the single run of that topic: `run.yaml` (state and the former run record), `ASKS.md`, `*.ask.md`/`*.reply.md`, `batches/`, `REPORT.md`, `NEEDS_YOU.md`, `claims.yaml`, `sources.yaml`, one `attempts.jsonl`, `drafts/`, `lessons/`, `media/` and `site/` (rendered pages laid out with their site-relative paths; the gates check `site/`). A media chapter is admitted as its own source (`sN`). An agent's fetch drop lands in `sources/`; the driver admits it as `sN.txt` and removes the drop. Anything an ask attaches lives under `run/` with a stable name (media downloads go to `run/media/`), so its hash is stable across processes and replays. `start` wipes `run/` and keeps `sources/` when the run is done or failed, refuses a waiting or suspended run unless `--restart`, and `resume` names only the topic because `run.yaml` stores `site_root` and `site_url`. A fix means a new run.

**0039 Publish in place.** Every run renders into `<state>/<topic>/run/site/` with the same relative paths the pages have on the site (`answers/<file>.html`, `<course>/...`), and the gates read that dir. Publishing takes `~/.rigor/publish.lock`, requires the clone to be on `main` with no uncommitted change in the paths about to be written, pulls `--ff-only`, copies the topic's rendered pages in (never a home index from the render dir), deletes any other file the clone holds for that topic (its footprint, shared with `rr remove`), stamps the publish time into `research-rigorously-date` on the committed pages, regenerates `index.html` and `assets/course-index.js` inside the clone so they list every published topic, `git add`s exactly those paths (deletions included), commits and pushes. Live check compares the published bytes against the clone — pages, the two index files and a 404 for every deleted path; on mismatch the publisher runs `git revert --no-edit <sha>` and pushes the revert. On pass the run is done and `~/.rigor/<topic>/` is deleted, `sources/` included. The ledger lives only in `run/`. Topic removal follows the same rule with the topic's file list, regenerates the index inside the clone, commits those exact paths, and reverts on a failed live check. Page heads carry the run record as meta next to mode and layout: `research-rigorously-answered-by`, `research-rigorously-date` (UTC, ISO, stamped at publish, inside the lock, on the pages being committed) and `research-rigorously-claims-<status>` for true, untrue, interpretive, not-found and unchecked. A course's kind and subject are `course-kind` and `subject` meta tags on its `index.html`, written by the renderer and read back from there.

**0040 One inline-dependency entry script.** The skill runs as `uv run <skill dir>/rr.py <command>`, with no flags. `rr.py` carries the only PEP 723 header, which lists every dependency (`pyyaml`, `jsonschema`), and hands off to `scripts.cli`. The modules under `scripts/` carry no header and import as the `scripts` package: uv builds and caches the script's environment itself.
**0041 Selfcheck is the check bar.** `rr selfcheck` runs the skill's checks in-process with no credentials, no network, no real `~/.rigor` and no real site: temp dirs, a temp bare git clone, and injected fetch/sleep/clock/switcher seams. It prints one `PASS name` or `FAIL name: reason` line, a final count, and exits 0 only when every check passes; `--list` names them and `-k <substr>` selects a subset. The set covers the deleted test suite's KEEP and ADAPT behaviours plus the regressions fixed since (key rotation, ceiling settlement, publish bytes, routing, key-file warnings), and the mechanical invariants (no build files, one header, generated routing, ask attachments under the run dir, SKILL frontmatter). The repo's `.githooks/pre-commit` runs it whenever a commit stages a path under `research-rigorously/`, so no check needs to be remembered by hand. It runs in seconds; a check that needs the network or a credential does not belong here.
**0042 URL audit second chance.** A cited URL the audit flags blocked or failed is rechecked through every non-MCP fetch route in registry order with the normal fetch ladder (`allow_mcp=False`), then by one gate-phase agent ask that names every MCP fetch tool from the registry (`tools.fetch.fetch`, `tools.tavily.tavily_extract`, ...). Any route with real content passes it. Only when every route fails does the gate fail, and the failure is appended to `<state root>/link-failures.jsonl` (via `Layout`): url, topic, date, and every route tried with its status/code. That file is the failing-links ledger.
**0043 One live check.** Publish and remove share `ship.live_check_until`: 12 attempts, 20 s apart, byte-compare against the clone and expect 404 for removed paths; there is no second policy.
**0044 Secrets files are service files.** `rr keys` reads only `<Service>.env` files whose stem maps to a registry pool (`Tavily.env`, `ScrapeGraphAI.env`, ...); it never opens unrelated `~/.secrets/*.env` files and warns only about the service files it reads. Usage columns come from each vendor's documented endpoint; where none exists (tinyfish) or the token lacks permission (brightdata 403) the row says so.

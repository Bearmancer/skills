name: github-create
description: "Use when filing an issue, PR or feature request on a third-party GitHub repo, or after root-causing a bug in a dependency or CLI. Runs unattended through latest-version gate, proven fix, PR, CI and cleanup."
---

Third-party repos only. The run is unattended and maximal: every step runs in full, and the stops are mechanical and fail closed (preflight, URL audit, loop limits). A post carries proof or is not filed: the reviewer checks every claim against source, diff or demo alone.

With no user to ask, the smaller reversible option (narrower scope, fewer claims) is taken and recorded under Decisions in the report. A thread that needs a maintainer decision stays `needs-triage` with the question in the comment.

Companions: `references/method.md` (method, delegation tiers, proof bar, closure table, corrections), `references/bodies.md` (issue and PR layouts, PR body craft, URL audit), `references/triage.md` (roles, outcomes, briefs and the unattended deltas), `references/ci-harvest.md` (one row of CI facts per repo doc). The bundled scripts `preflight.py` and `rebase-gate.py` live in this skill's `scripts` folder; below, `preflight <command>` and `rebase-gate <command>` mean `uv run --script` on that script from there.

## Shape

Symptom, no fix, or unclear → issue. Missing capability → feature issue, then the implementing PR. Fix for an existing bug, or root cause confirmed in the repo's own code with the fix building and testing green in the clone, and the repo takes PRs → issue first, then the fix PR (`Fixes #<n>` with the filed number). An existing thread on the same mechanism, or a CONTRIBUTING rule, can change that: `method.md` "Closure table".

## Path

An existing-thread search, one shared setup, then two pipelines in order. The issue pipeline runs to a filed, updated or adopted issue (or ends on an existing PR) before any fork, branch or fix. The PR pipeline starts only when that issue exists (or the repo is PR-only), a fix is confirmed in the clone, and the repo takes PRs. Each step ends on a checkable criterion.

0. **Existing thread first.** If the request names no repo — a bare issue number, or a product whose upstream and the user's own forks are all in reach — resolve the target before exploring: `gh search issues author:<user> --sort updated` (omit `--state`; the default spans all), open the top hits and check author and subject against the request; still ambiguous → ask with the question tool, never hunt repos. Then, before the version gate, the clone, the index or any fork, search the target repo's issues and PRs by concept in three phrasings (symptom, mechanism, capability) with `gh search issues --include-prs` and no `--state` filter (the default spans open and closed; `--state` accepts only open|closed), and open every candidate thread in full, comments included (`method.md` "Read in full"). Any working `gh` will do here; the latest-release requirement starts at step 1. An open issue or PR on the same mechanism that is sound (not thin, per `method.md` "Existing thread") ends the run: report the thread's link, its state and any open fix, and nothing is cloned, indexed, forked, posted or commented. A comment on that thread is a separate request from the user, not part of this run. No covering thread, a thin one, or only closed matches that the "Closure table" says to refile → continue to step 1 and carry the candidate list into step 3. _Done when:_ the target repo is named (resolved or asked), the searches run are named and either the run has ended on a sound open thread or the candidate list is recorded.

1. **Version gate and workspace.** `preflight latest` first: `gh` and `codegraph` must each be on their latest release. Any non-zero exit ends the whole run: no clone, no post; report the printed `STALE:` lines, each ending in its `repair:` command. An unanswerable probe counts as stale. Then every run makes its own fresh clone of the latest default branch (a cached clone is stale by definition) in a run directory of its own, so every clone, write and delete touches that directory only. In a bash shell: `d=$(mktemp -d -t gh-<repo-slug>-XXXXXX)`. `gh repo clone <owner>/<repo> "$d/repo" -- --filter=blob:none`; the first command after the clone is `cd "$d/repo" && codegraph init -y`, before any read, search, fork or branch, so every later trace and subagent brief runs on the index. `-y` keeps init non-interactive for the unattended run. Confirm `codegraph status` answers and keep the index out of the diff with `grep -qxF '.codegraph/' .git/info/exclude 2>/dev/null || echo '.codegraph/' >> .git/info/exclude`. Then `git rev-parse HEAD` (the SHA every citation pins to). Fork, branch and code edits wait for the PR pipeline. Init fails → stop and report. _Done when:_ `latest` exits 0, and the clone is at default-branch HEAD in the run directory, the index is built and the SHA noted. Body files and notes live in `$d`.

### Issue pipeline

2. **Repo doc and issue contract.** `preflight repodoc "$d/repo" <owner>/<repo>` fetches the CI/CD facts (PR workflows and their `run:` lines, title lint, DCO/CLA, merge methods, required checks, recent failed PR runs, policy files) into the repo's own doc, kept with the skill as `<owner>__<repo>.md` (`GITHUB_CREATE_STATE_DIR` moves the folder), and prints it. Every `repodoc` and `learn` write is locked and stays on disk; nothing is committed or pushed. Read the whole doc, every earlier Learning included: each Learning is a rule for this run's draft and checks. Then `preflight contract "$d/repo" issue`, then read every file it lists in full, including the issue template or form, and fetch any linked AI or contribution policy. Classify the AI policy: `allowed`, `disclose` (note the exact disclosure text) or `forbidden` (bans AI-written or autonomous contributions: file nothing, report the quoted rule). PR-only repo: run only `repodoc` here, then the PR contract at step 9. _Done when:_ each listed file is read, the issue template's headings and fields are known, and the title rule, sign-off and AI policy are known.

3. **Triage and verdict.** Start from step 0's candidate list, adding any thread the contract files or the clone point to, and open each new one in full. Verdict per `method.md` "Existing thread", its "Closure table" and `references/triage.md`: new issue, update or comment an existing issue, an existing PR that ends the issue pipeline, or PR-only. Record the category (`bug`/`enhancement`) and state (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`), flagging a conflict. _Done when:_ a verdict, category and state are stated with the threads read and the searches run (named in the draft), any update target is named by number, and the report says whether the PR pipeline is allowed.

4. **Reproduce and locate.** Run a red loop per `method.md` "Root cause" step 1 and minimise it; locate the mechanism with codegraph (`method.md` "Codegraph") and open the cited file to quote the line. Rank hypotheses only when the issue will claim a cause; otherwise write "mechanism not confirmed" and keep the issue to the observed failure. _Done when:_ a red loop (or a feature's observed failure) and minimal repro exist, and the issue has either a `path:line@SHA` mechanism with its call path or an explicit unconfirmed note.

5. **Draft and check the issue.** Draft to `$d/issue.md` per the issue template or form, else `bodies.md` Issue or Feature issue. `preflight check "$d/repo" issue --body "$d/issue.md" --title "<title>" --ai-policy none|allowed|disclose|forbidden [--disclosure "<text>"] [--template <name>]`, then the URL audit (`bodies.md` "URL audit"). With a repo template or issue form the check covers every heading or form field, required validations, dropdown values, required checkboxes, title prefix and lint, and sign-off. _Done when:_ exit 0 and every URL passes; exit 3 is a refusal (forbidden AI policy, blank issues disabled, several templates): file nothing, report the printed rule. The same violation three rounds running → file nothing, report it.

6. **File, update or adopt the issue.** New: `url=$(gh issue create --repo <o>/<r> --title ... --body-file "$d/issue.md")`; `number=${url##*/}`. Existing issue: fetch the current body (`gh issue view <n> --json body --jq .body`), append the new material, then `gh issue edit <n> --body-file` when you own it or have WRITE, else comment the missing evidence; `--body-file` replaces, so the body passed carries the original plus the addition. An existing open PR covering the mechanism is updated or commented and ends the issue pipeline: no new issue. Comments and issue updates carry the `references/triage.md` banner; an existing thread's outcome follows its `ready-for-agent`/`ready-for-human` brief, `needs-info` template, `wontfix` close, or `needs-triage` record. Feature issue: record `PR status: planned in this pass` (or leave the field if the template has none). _Done when:_ the issue URL and number are recorded, or the existing PR is the recorded target, and the PR pipeline has its input.

### PR pipeline

A symptom-only issue stops here.

7. **Fork and branch.** `gh repo view --json viewerPermission`; READ, TRIAGE or none → `gh repo fork <owner>/<repo> --clone=false`, `git remote add fork <fork-url>`, `git switch -c <branch>`; WRITE or above → `git switch -c <branch>` on `origin`, no fork. Either way the branch starts at default-branch HEAD (CONTRIBUTING's naming, else `fix/<mechanism>`); push to a feature branch only. _Done when:_ the remote for the push exists and the branch is at default-branch HEAD.

8. **Confirm root cause and fix.** Run the full `method.md` "Root cause", then its "Fix and test (PR pipeline)". Then the live test: build and run the repo's real entry point (CLI, server, plugin host, app) on base and with the fix against step 4's reproduction in the clone, and capture both outputs verbatim; they become the PR's before/after evidence. A fix that only passes its unit test is unproven. _Done when:_ the root cause is confirmed, the regression test went red on base and green with the fix, the live run shows the symptom on base and gone with the fix, the repo checks pass, and the self-review is recorded.

9. **PR contract and draft.** `preflight contract "$d/repo" pr`, read every file it lists in full, including the PR template, then draft to `$d/pr.md` per the repo's PR template, else `bodies.md` PR. The body carries `Fixes #<number>` from step 6 (or `Related #<n>` when the issue is not fully fixed), the evidence pair and the base SHA. _Done when:_ the PR template is known and the draft carries the issue number and the before/after evidence.

10. **Check and file the PR.** `preflight check "$d/repo" pr --body "$d/pr.md" --title "<title>" --ai-policy none|allowed|disclose|forbidden [--disclosure "<text>"] [--template <name>] --base origin/HEAD`, then the URL audit. Run `git push -u <remote> <branch>` (`fork` in the fork path, `origin` for WRITE), then `gh pr create --repo <o>/<r> --base <default> --head <head-owner>:<branch> --title ... --body-file "$d/pr.md"`, where `<head-owner>` is the fork user or the upstream owner for WRITE. Feature: comment the PR link on the issue. A failed push or PR create → `gh issue edit` the issue to **PR status: blocked by <reason>**. _Done when:_ every URL is recorded, the issue number appears in the PR body, and the issue links the PR when one was created.

11. **CI.** Before filing, record the base commit's check state (`gh api repos/<o>/<r>/commits/<sha>/check-runs --jq '.check_runs[] | {name,status,conclusion}'`) so a pre-existing red is not read as the PR's. After create or update: `gh pr view <n> --json statusCheckRollup,mergeable,reviewDecision` for the snapshot, then `gh pr checks <n> --repo <o>/<r> --watch --fail-fast` (long: run detached). Without `--json`, `gh pr checks` exits 8 while any check is still pending (1 on a failure; with `--json` it always exits 0): exit 8 is pending, not failed, and a check failed only when its `bucket` is `fail` or `cancel`. A real failure → root-cause in the clone, new commit, push to the same remote; at most three rounds, then report. Failing CI updates the repo doc by itself: after every checks snapshot run `preflight learn <owner>/<repo> --from-pr <n>`, which records each failed check (workflow, job, log tail, run link) as a Learning with `fix: pending`, deduplicated by check link (it refuses when `gh pr checks` cannot be read, e.g. a repo with no workflows: skip it there). When the PR already went green, use `learn <owner>/<repo> --from-run <run_id>` instead: it records the failed jobs of that run, which `--from-pr` no longer sees. Once the fix lands, `preflight learn <owner>/<repo> "<failure> -> <fix or rule>"` records the resolution; maintainer change requests and rejected pushes get the same `learn` entry, so the next PR to this repo meets each of them before filing. `action_required` (maintainer approval pending) → report it as pending and continue. Maintainer questions and a CLA that needs a human are listed as pending, not worked around. CI applies to PRs only. _Done when:_ checks are green, or the bounded report names each failure or pending item.

12. **Re-audit.** A light subagent re-opens every cited line at the SHA and every posted claim from GitHub — the issue, the PR and any thread updated in place — and returns match or mismatch; the main loop fixes or deletes mismatches (`method.md` Corrections). _Done when:_ zero mismatches. Corrective body edits re-run `preflight check ... --amend` (skips diff-against-base; allows a documented unchecked box with an explanatory note); normal runs stay strict.

13. **Cleanup.** Remove the run directory and nothing else. `cd /` first, so the current directory is not inside the tree being deleted, then guard the delete by name: `case "$(basename "$d")" in gh-*) rm -rf "$d";; *) echo "refusing to delete $d" >&2;; esac; test ! -e "$d"`. The guard is what makes the delete safe: an unset `$d`, or one step 1 did not make, is refused outright. On every exit path including refusals and a stopped issue pipeline. The fork or remote branch stays on GitHub: the PR lives there. _Done when:_ the run directory is gone.

The report opens with the remaining-items count, then URLs, preflight result, Decisions taken, the Learnings recorded this run, and what waits on others.

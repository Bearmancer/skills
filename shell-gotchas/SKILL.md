Known shell foot-guns, verified in this environment. Check this list before debugging a shell error from scratch.

## PowerShell

- `$Host` is a read-only auto var (`Cannot overwrite variable Host`). Name the param or var `$ApiHost`.
- Double-quoted string: var followed by `?` or a scope-prefix char (letter/`_`, e.g. `:`) breaks interpolation, resolves silently empty. `"$var?query=..."` → empty; `"#$n: $_"` → `$n:_` parsed as drive var, empty. Fix: brace `${var}` or subexpression `$($var)` — `"${var}?query=..."`, `"$($r.Status)?x=1"`, `"#${n}: $r"`, `"#$($n): $r"`.
- `Compress-Archive -Path $files.FullName` with `$files` a flat array from `Get-ChildItem -Recurse -File` flattens dirs — all files land at zip root. Pass top-level `Get-ChildItem $dir` items instead to preserve subtree.
- `Get-Volume -FileSystemLabel "X"` can return nothing on a mounted volume (WMI cache stale). Use `Get-CimInstance Win32_LogicalDisk | Where-Object VolumeName -eq "X"`.
- NTFS case-only rename (`tv`→`TV`) can no-op in one `Rename-Item` call. Two-step via temp name:
  ```powershell
  Rename-Item -Path $path -NewName "$leaf.__tmp__"
  Rename-Item -Path "$path.__tmp__" -NewName $newCasedName
  ```
- Mutating fields piped through `Where-Object` doesn't persist — pipeline output is a copy. `($items | Where-Object {...}).value = "x"` hits the copy, fails silent. Use `foreach ($i in $items) { if (<cond>) { $i.value = "x" } }`.
- Building a string with literal double quotes (e.g. `-File "path with spaces"` as one flag value): double-quoted PS strings need escapes (`` `" `` or `""`). Wrap the outer string single-quoted instead — literal, no escaping needed: `'--params=-NoProfile -File "C:\path with spaces\script.ps1"'`. Use double-quote+escape only when the value needs interpolation.
- Give `-replace` a string pattern: a bool (`$T.Contains(x)`) coerces to `"True"` and deletes every `true` in memory.
- Native command output assigned to a variable is an ARRAY of lines, not a string: ``$b = gh pr view --json body --jq .body`` then ``$b.Substring(0,300)`` throws ``Index and length must refer to a location within the string`` because ``$b`` is ``Object[]`` and ``.Length`` is the line count. Join first (``$b = ($b -join "`n")``) or write to a file and process that.
- Read `$LASTEXITCODE` after native CLIs — parse/count failures surface there, not stdout.
- `try { ... } catch { ... }` catches nothing unless the cmdlet throws a _terminating_ error — most cmdlet failures (missing path, etc.) are non-terminating: the error prints, the catch block never runs, execution continues. Fix: `-ErrorAction Stop` on the guarded call (`try { Get-Item $p -ErrorAction Stop } catch { ... }`).
- The reverse: under `$ErrorActionPreference = 'Stop'`, `Write-Error` is terminating. Inside a `catch` it ends the block on that line, so the cleanup, log line and `throw` after it never run (a wizard's fatal handler logged nothing and uninstalled nothing). Report with `Write-Warning` or a log function, then `throw`.
- `-ErrorAction SilentlyContinue` on a query (`Get-AppxPackage`, `Get-WindowsOptionalFeature`) returns nothing when the query itself fails, which reads as "not installed". Use `-ErrorAction Stop` in `try`/`catch` and treat the catch as unknown, never as absent.
- `Select-Object -Unique` does not compare `[pscustomobject]` properties: three distinct objects (`A=1`, `A=2`, `A=3`) came back as one, so a cleanup removed one dead PATH entry of many. Deduplicate by key: `Sort-Object Scope, Entry -Unique` kept all three. Plain strings are fine.
- `Start-Process -Wait` leaves `$LASTEXITCODE` at its previous value (stayed 7 after a child exited 3) and has no timeout. Use `-PassThru` and read `.ExitCode`, or `[System.Diagnostics.Process]` with `WaitForExit(ms)` for a deadline.
- `Win32_Process.Name` includes `.exe` (`pwsh.exe`, `WindowsTerminal.exe`); `Get-Process` `.ProcessName` does not. A name regex anchored without `.exe` (`^(Code|opencode)$`) never matches CIM results.
- Store (MSIX) pwsh 7.6.9 at `C:\Program Files\WindowsApps\Microsoft.PowerShell_*`: `Get-WindowsOptionalFeature -Online` failed with `Class not registered` or hung past 120 s, while Windows PowerShell 5.1 returned `State: Enabled`. Use `dism.exe /Online /English /Get-FeatureInfo /FeatureName:<x>` (needs elevation; exit 740 otherwise), and check `(Get-Process -Id $PID).Path` for which pwsh is running; `$PSVersionTable` does not say.
- The same Store pwsh cannot load the Appx module: `Get-AppxPackage` fails with `Operation is not supported on this platform. (0x80131539)`, because .NET 5+ dropped built-in WinRT. `Import-Module Appx -UseWindowsPowerShell` works only by running a hidden Windows PowerShell 5.1 process.
- Windows PowerShell 5.1 `ConvertTo-Json` writes an enum as its number (`DayOfWeek.Monday` → `1`), so a feature `State` read back through JSON never equals `'Disabled'`. Make it a string first: `@{ n = 'State'; e = { "$($_.State)" } }`.
- `pwsh -Command 'cmd /c exit 3010'` exits 1, not 3010: a failing native command at the end of `-Command` becomes exit 1. End the command with `; exit $LASTEXITCODE` to pass the real code through.
- A `ShouldProcess` function with `ConfirmImpact = 'High'` prompts under the default `$ConfirmPreference` (`High`) and throws `MethodInvocationException` under `-NonInteractive`. Setting `$ConfirmPreference = 'None'` silences it by auto-confirming every call, including the destructive ones. Ask with an explicit yes/no prompt and use `ConfirmImpact = 'Medium'`.
- `Read-Host` takes whatever is already in the console input buffer: an Enter pressed during an earlier unattended step satisfied a later "press ENTER when done" prompt in the same second. Drain first: `while ([Console]::KeyAvailable) { [void][Console]::ReadKey($true) }`. With input redirected, `Read-Host` returns at once; check `[Console]::IsInputRedirected`.
- With QuickEdit on, a click in the console (easy after a GUI installer steals focus) starts a selection and freezes output and input until Space or Esc, so Enter seems to need Space first. Clear `ENABLE_QUICK_EDIT_MODE` (0x40) through `SetConsoleMode` for the script's lifetime and restore the old mode in `finally`. `skills/ps-wizard/template.ps1` has the code.
- A PATH entry must be a directory: `...\Bitwarden\bws.exe` added to User PATH was ignored; `...\Bitwarden` works. Shells already open keep their old `$env:Path`; check a new install from a new process.
- `bun remove -g <pkg>` recreated `~/.config/opencode`, `~/.local/share/opencode`, `~/.local/state/opencode` and `~/.cache/opencode` deleted seconds before. Run package-manager uninstalls first, then delete leftovers, then rescan.
- A bash-style escape inside a PowerShell single-quoted string keeps `\"` literal: `New-Service -BinaryPathName '\"C:\app\x.exe\" -service'` bakes backslash-quotes into the service PathName and SCM start fails with `The system cannot find the file specified` (System log event 7000). Space-free paths need no quoting at all; for paths with spaces use the literal-double-quote pattern above. Verified 2026-10-31.
- `Win32_Service.PathName` is read-only to `Set-CimInstance` (`Could not modify readonly property 'PathName'`) — change a binPath with `sc.exe config <svc> binPath= ...` or by recreating the service. Recreation is safe immediately: `sc.exe delete` releases the name at once (probe recreate with no wait succeeded 2026-10-31), disproving any sleep-for-SCM-release folklore.
- `$env:APPDATA` already ends with `\AppData\Roaming` (`$env:LOCALAPPDATA` with `\AppData\Local`) — appending `Roaming` builds a phantom path and `Start-Process` reports `The system cannot find the file specified` for a real executable. Compose from the variable directly: `"$env:APPDATA\Emby-Server\system\EmbyServer.exe"`. Verified 2026-10-31.

- A bare `---` between commands is parsed as the unary `-` operator (`The '--' operator works only on variables or on properties`). A separator between statements must be quoted: `Write-Output '---'`.
- A path bare in an expression after a variable expansion — `$env:LOCALAPPDATA\npm\pnpm.cmd` — is a ParserError (`Unexpected token '\npm\pnpm.cmd'`). Quote it or build it with `Join-Path $env:LOCALAPPDATA 'npm\pnpm.cmd'`.
- Native stderr arrives wrapped: the shell tool's PowerShell layer turns any bytes a native command writes to stderr into a `NativeCommandError` block that re-echoes the full command line — progress bars (gh clone), rg flag errors, gh usage text all produce a wall that looks like a crash. Harmless: the command still ran; read stdout and `$LASTEXITCODE`.
- Any inline interpreter program handed to PowerShell gets parsed by PowerShell itself and dies before the interpreter starts. `python -c "..."` containing `??`, parentheses or f-strings → `Unexpected token '??' in expression or statement` / `An expression was expected after '('`, with the error pointing at `line:1 char:N` of the shell command, not at Python. Same trap for `node -e "..."` and for `gh --jq '{a: .x, b: .y}'` expressions containing spaces: gh then reports `accepts at most 1 arg(s), received 2`. Fix: write the program to a `.py`/`.mjs` file with the file tools and run the file; or pipe raw `--json` output to `ConvertFrom-Json` and handle it in PowerShell. Verified 2026-10-31.
- A PowerShell here-string (`Add-Content -Value @" ... "@`) passed through the shell tool is rejected before execution: `Portable shell scanner cannot analyze command: invalid-structure`. Fix: append or write file content with the file tools (edit/Write), never a here-string. Verified 2026-10-31.

- Python-based CLIs (tvly and friends) raise UnicodeEncodeError (cp1252) on non-ASCII output under PowerShell unless the same shell invocation first sets $env:PYTHONIOENCODING=utf-8 and [Console]::OutputEncoding=[Text.Encoding]::UTF8; observed 2026-10-31 in discovery lanes, fixed live with exactly that preamble.

## Bash tool (git-bash on Windows)

- Bash tool cwd doesn't persist a `cd` across calls — each call may reset to the tool's default dir. Use `git -C <dir> <cmd>` or an absolute path per-command, not `cd dir && cmd`.
- Bash `>` redirect of a command's stdout (git-bash) can add line-ending artifacts: `Invoke-Formatter` threw `Cannot determine line endings as the text probably contain mixed line endings` only on bash-redirected round-trips, never chained inside one `pwsh` session (`$text | Invoke-Formatter`). Reproduce in-process before blaming the tool.
- `rg -c` on zero matches prints nothing, exit 1 — reads as crash, means success. Confirm via `Read`/`grep` tool.
- Double-quoted Windows path ending `\` (`ls "C:\dir\"`): trailing `\"` escapes the quote → `unexpected EOF while looking for matching '"'`. Drop trailing slash or use forward slashes.
- A PowerShell command passed in bash double quotes (`pwsh -c "1..2 | ForEach-Object { $_ }"`) loses its pipeline variable: bash expands it first to the last argument of the previous command, so pwsh runs that word as a command (`The term 'marker' is not recognized`). Single-quote the pwsh command, or escape the dollar sign with a backslash.
- `/usr/bin/time` is absent and `time` is only the bash keyword. Take wall time from `date +%s%N` deltas: `a=$(date +%s%N); <cmd>; b=$(date +%s%N); echo $(( (b-a)/1000000 )) ms`.
- A `.bat` that counts lines with `for /f %%n in ('find /c /v ""') do ...` hangs when started from git-bash: GNU `find` comes before `find.exe` on the inherited PATH and walks `/c` instead of counting. Count with a `usebackq` loop over the file: `for /f "usebackq delims=" %%l in ("%~1") do set /a c+=1`.
- Foreground `sleep N && cat <task output>` blocked by harness. Background task notifies on exit; waiting on a condition → Monitor.
- Long or unknown-duration shell work in the eval kernel carries an explicit `timeout`, or runs via `Bun.spawn` (which stays stoppable). An un-timed `Bun.$` that hangs parks the whole serial JS kernel: queued cells wait behind it, an identical `peek` loop trips the repetition guard, and stopping the hung cell restarts the kernel and drops every global.
- Repeated state surveillance (PR/issue checks, file watches) runs as ONE `tool.monitor` command whose filter prints only on change (diff against a saved baseline in `$SENPI_MONITOR_STATE_DIR`); per-turn `peek`/`gh pr view` re-polls of identical state trip the harness repetition guard — this session burned 11 identical peeks before the interrupt.

## Bun eval kernel (Bun.$)

- `Bun.$` runs in the tool's default cwd (the home dir), not your working directory — every mutating command (`bun install`, `bun run`, `git commit`) carries its own `cd <target> &&` or a `-C` flag. A misdirected `bun install` wrote 627 packages into `~/node_modules` where removal then hit `EPERM`.
- Interpolating an array as one `${arr}` template slot sends a SINGLE argument — the shell never word-splits it, so `git -C ${wd} ${args}` fails with a cryptic exit 128. Spread each element (`${args[0]} ${args[1]}`) or loop them explicitly.
- `gh pr view --json mergeable` reads `UNKNOWN` right after every push while GitHub recomputes — bound the recheck (e.g. 4 × 20 s poll inside one cell, breaking early on non-UNKNOWN) instead of ad-hoc retries, and fold the whole wait into the monitor from the Bash section; likewise cap exploratory directory walks (`readdir` slice, `depth`, `head`): one fixups tree walk dumped hundreds of unasked-for lines into the cell output.

- A Windows path with backslashes passed through a `Bun.$` template loses them: `git clone <url> C:\Users\me\x` cloned into a relative folder named `Usersmex` under the cwd. Pass forward-slash paths (`C:/Users/me/x`) and read the destination back.
- A top-level `const crypto = require("crypto")` in one cell followed by `delete globalThis.crypto` removes the real global; a later `Bun.WebView` then fails with `crypto is not defined`. Restore it with `globalThis.crypto = require("node:crypto").webcrypto` or restart the kernel.
- A recursive `Select-String` over `~/.omo/agent/runtime` outran the cell budget and restarted the kernel. Use `rg -l --max-filesize 6M` through `Bun.spawn` with a `timeout`.
- `String.replace(from, to)` reads `$` patterns in `to`: a replacement that mentions `Bun.$` followed by a backtick inserted the text before the match and duplicated half a file. Pass a function, `replace(from, () => to)`, and check `git diff --stat` before committing an edit made from a cell.

## JSON tools

- Use `jaq` for JSON here — same CLI/filter syntax as `jq`, stricter parsing catches bad escapes.
- `jaq`/`jq`/`ConvertFrom-Json` all reject trailing commas. Tolerant path: pwsh + dotnet `[System.Text.Json]` with `AllowTrailingCommas`+`JsonCommentHandling.Skip`, mutate via `JsonNode` — no regex surgery. No `json5`/`commentjson` Python libs on box, no `gojq`/`yq`/`dasel` either. Fallback: `sd`-strip `,\s*}` / `,\s*]` → `jaq`.
- `jq`/`jaq` can't sit mid-PowerShell-pipeline: `... | jq .id` throws `InvalidOperation: Cannot run a document in the middle of a pipeline` — native stdin executables only work at pipeline end or standalone. Prefer `jaq` (project rule); it only works at pipeline end too, so for anything nontrivial write the JSON to a file and run `jaq -f filter.jq file.json`.
- Inline filter expressions with double quotes never reach `--jq`, `jaq`, or `rg` intact: this shell strips inner `"` from quoted args. `--jq '.name+"|"+.status'` arrives as `.name+|+.status` (`failed to parse jq expression: unexpected token "|"`), `jaq 'test("a|b")'` arrives as `test(a|b)` (`undefined filter`), `rg 'https?://[^) " ]+'` gets `regex parse error: unclosed character class`. Rules: keep inline filters space-free AND quote-free (bare paths: `--jq .items[].url`; joins via `@tsv`: `--jq '.items[]|[.name,.state]|@tsv'`); any filter containing literals goes in a file — `jaq -f filter.jq file.json`, `rg -f pattern.txt`, or GitHub permalink patterns see gh CLI.
- Readback of a posted body is file work, not variable work: `gh pr view --json body | Out-File f.json` yields ONE line, so `rg -c 'a|b|c' f.json` prints `1` however many markers matched — `-c` counts lines, not occurrences. Count per marker: `rg -o -N -- <marker> f.json | Measure-Object -Line`, one marker per command; `-o` patterns containing `|` need `-F` or a pattern file.
- Hand-building JSON in a single-quoted bash `echo` with a Windows path (`C:\Users\...`): backslashes pass through literally → invalid escapes (`\U`, `\L`, ...). Fix: forward slashes, or double every backslash (`C:\\Users...`) — JSON parsers accept both.
- Same bug hits heredocs, doubling math worse: the Bash tool's `command` param is JSON-decoded by the harness before bash sees it (one backslash-halving layer already spent), then a quoted heredoc (`<<'EOF'`) passes bytes through literally. What you write as `C:\\Users` (2 backslashes) can land as `C:\Users` (1) in the file. Fix: forward slashes always — sidesteps counting escaping layers.
- `ConvertTo-Json` defaults to `-Depth 2` and destroys deeper data with only a warning — level 3+ renders as `"System.Collections.Hashtable"` (`WARNING: Resulting JSON is truncated as serialization has exceeded the set depth of 2`). Fix: always pass an explicit depth (`... | ConvertTo-Json -Depth 5`). The reverse direction is safe: `ConvertFrom-Json` preserves full depth.

## gh CLI

- `gh api` sub-issue endpoint (`/issues/{n}/sub_issues`) needs the integer database ID, not the GraphQL node ID. `gh issue view N --json id` returns the node ID (`I_kwDO...`) → REST rejects with HTTP 422 "not of type integer". Get the int: `gh api repos/{owner}/{repo}/issues/{n} --jq .id`. Use `-F "sub_issue_id=$id"` (not `-f`) so it's sent as a number.
- `gh api` GET endpoints (contents, commits) reject `-f ref=dev` — the flag is for POST/query-free requests here and returns a bare 404. Pass the parameter inline: `gh api repos/<o>/<r>/contents/CHANGELOG.md?ref=dev`, and quote the WHOLE endpoint when it contains `&` (`"repos/.../commits?sha=dev&path=<file>&per_page=3"`), because an unquoted `&` in a `Bun.$` template backgrounds the command and fails with `Background commands "&" are not supported yet`. NOTE 2026-10-31: in the shell tool's PowerShell layer `&` splits native args EVEN INSIDE single quotes — `gh api 'search/issues?q=a&sort=b'` → `accepts 1 arg(s), received 4`; passing query params as repeated `-f key=value` also fails when the endpoint needs quoting anyway — for multi-param GETs quote the whole endpoint AND avoid `-f`.
- `gh api` relative endpoints work only because gh special-cases most paths; `search/...` is not one of them. `gh api search/issues -f q=...` returns a bare `{"message":"Not Found"}` HTTP 404 for ANY parameter shape (probed: space value, no-space value, `-X GET`, full URL) — the fix is the leading slash: `gh api '/search/issues?q=author:X'`. Do not blame quoting when a `search/` 404s; add the slash and it returns 200.
- `gh --json` field vocabularies differ per command and punish guessing: `gh search issues` has `url`, not `htmlUrl`; `gh issue view` has `closedByPullRequestsReferences`, not `closedBy`; `gh pr view` has `state`/`closed`, not `isOpen`. An invalid name exits 1 and prints the full available-field list — read that list and pick from it; never retry with a synonym.

- `gh search issues` and `gh search prs` reject `--state all`: `invalid argument "all" for "--state" flag: valid values are {open|closed}` (hit while following a skill that prescribed `--state all`). Omit `--state` instead — the default already searches all states, and `gh search issues --include-prs` returns issues and PRs of every state (open, closed, merged) in one call; `--state` only narrows. Verified 2026-10-31.

## Third-party process spawners with own JSON "command" field (dprint exec, etc.)

- A tool that reads a shell command from a JSON config value (dprint `exec`) tokenizes it itself, a third quoting dialect; nested escaped quotes split wrongly. Put the logic in a script file and make `"command"` quote-free: `pwsh -NoProfile -File "C:\path\script.ps1" "{{file_path}}"`.
- Omitting `{{file_path}}` runs on empty input (dprint: "the formatted text was empty"). Read the file (`Get-Content -LiteralPath $Path -Raw`), not stdin, to avoid the mixed-line-endings bug. Verify with the real invocation (`dprint fmt`, twice).

## Python

- Run Python only through `uv run`, for example `uv run --no-project --with pytest python -m pytest`. A bare `python` or `python3`, including inside a heredoc, is blocked by a hook.
- Write any script that contains backslashes with the Write tool, not a bash heredoc. The heredoc path halves backslashes (see JSON tools above).

## uv, npx and topgrade

- Node 25+ ships no corepack (`The term 'corepack' is not recognized`), so a repo whose CONTRIBUTING says `corepack prepare pnpm@X` has no entry point. Run the repo-pinned pnpm with zero global installs: read the pin first — `packageManager` in package.json — then invoke `npx -y pnpm@<pin> install --frozen-lockfile` and `npx -y pnpm@<pin> exec <tool> run <file>`; `exec` resolves the repo's own binaries after install. Verified 2026-10-31 on Node 26.13 with a pin of 11.7.0: fresh install in 34 s, test file green, hooks via the repo's `prepare` script.
- `uv tool install <library>` fails with `No executables are provided by package` and removes the package again; uv tools are for programs. A test dependency goes through `uv run --with <pkg>`.
- `uv run <script>.py` keeps one cached environment per script whatever the interpreter. When the same script next resolves to another interpreter (a new `.python-version` pin, or `--python 3.12` after a 3.15 run), uv 0.13.1 on Windows fails to rebuild it: `failed to remove directory ...\environments-v2\<script>-<hash>\Lib ... (os error 32)`, exit 2, even with no other process running. Remove the script environments built for the old interpreter and uv rebuilds them on the next run: `Get-ChildItem "$env:LOCALAPPDATA\uv\cache\environments-v2" -Directory | Where-Object { (Get-Content "$($_.FullName)\pyvenv.cfg" -ErrorAction SilentlyContinue) -match '^version_info = 3\.15' } | Remove-Item -Recurse -Force` (change `3\.15` to the old version). For a one-off run on another interpreter, `UV_NO_CACHE=1` skips the cache.
- `npx skills experimental_install` clones one repository per skill, about 5 minutes for 67 skills. Run it detached or under a monitor, never as a foreground step.
- `topgrade --only <step>` overrides `disable`, so a disabled step still runs under it. Test a `disable` change with a full `topgrade --dry-run` and look for the step header; `--dry-run` prints each command without running it.

## Browsers and spawned processes

- A Chromium-based browser (Vivaldi) started headless with `--headless=new --screenshot=<file>` and a temporary `--user-data-dir` wrote no file here and left child processes holding the profile folder (`EBUSY` on delete). Stop only processes whose command line holds the profile marker, then remove the folder.
- A kill-by-marker script must not hold the marker in its own command line: it matched its own PowerShell and ended itself before printing. Build the marker from two pieces (`'sbx-' + 'abc'`) and exclude `$PID`.
- Directory symlinks (`New-Item -ItemType SymbolicLink`, `os.symlink(..., target_is_directory=True)`) need no elevation here: Developer Mode is on (`AllowDevelopmentWithoutDevLicense = 1`).

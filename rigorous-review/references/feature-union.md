# Feature union — where every source feature lives in `rigorous-review`

Sources: **CR** Matt `code-review` · **CQ** Addy `code-review-and-quality` · **RQ** Superpowers `requesting-code-review` (+ its `code-reviewer.md` template) · **RC** Superpowers `receiving-code-review` · **OMO** `review-work` · **OMC-R** OMC `review` skill · **OMC-A** OMC `code-reviewer` agent.

## Severity mapping (the one canonical scale)

| Canonical | CR/CQ                                                 | RQ template            | OMC-A       | OMO gate                                 |
| --------- | ----------------------------------------------------- | ---------------------- | ----------- | ---------------------------------------- |
| BLOCKER   | Critical:                                             | Critical (Must Fix)    | CRITICAL    | blocking issue                           |
| MAJOR     | (no prefix) Required / presumptive blockers escalated | Important (Should Fix) | HIGH        | blocking when tied to goal/constraint/QA |
| MINOR     | —                                                     | Minor (Nice to Have)   | MEDIUM      | NOTE                                     |
| NIT       | Nit:                                                  | —                      | LOW (style) | NOTE                                     |
| NOTE      | Optional:/Consider:/FYI                               | Recommendations        | LOW         | NOTE                                     |

Confidence (OMC-A HIGH/MEDIUM/LOW) rides on every finding. Verdict: BLOCKER/MAJOR@HIGH blocks; low-confidence BLOCKER/MAJOR → Open Questions, non-blocking (OMC-A #1335 pattern, kept). CQ's "presumptive blockers" (relocating refactors, file-size growth without decomposition, feature logic in shared modules, near-duplicate helpers, silent fallbacks) surface with a proposed simpler design and escalate to MAJOR only when the change actively worsens structure.

## Conflicts resolved (not just concatenated)

| Conflict                                      | Sources                                                                                                                 | Resolution                                                                                                                                                                                       |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Panel vs one reviewer; default breadth        | CR/OMC-R two parallel axes; OMO exactly one gate reviewer; owner instruction: default to ALL axes/modes/metrics         | Default (no flag) runs both, sequenced not blended: two-axis lanes first (parallel, apart), then manual QA, then ONE gate reviewer consuming their reports. `--mode=axes                         | gate | request | receive` narrows to exactly one. The "never add lanes" rule binds inside gate mode; the axes are a different job feeding it, not extra gate lanes. |
| Five severities vs four vs three+notes        | CQ, OMC-A, RQ, OMO                                                                                                      | One canonical 5-level scale + confidence; mapping table above; every source term maps deterministically.                                                                                         |
| Surface everything vs verify before reporting | OMC-A discovery recall; OMC-R/CQ verify-then-report                                                                     | Sequential stages: discover with severity+confidence, verify against callers/guards/tests, report survivors; low-confidence survivors go to Open Questions instead of being dropped or blocking. |
| Advisory vs gating                            | OMC-R advisory-by-default; OMO gate PASSED/FAILED; CQ merge-blocking severities                                         | Advisory findings always; a _verdict_ blocks only in gate mode or when configured gates say BLOCK, and hard release/security gates stay outside this skill and fail closed.                      |
| Reviewer subagents                            | RQ dispatches one reviewer; its template forbids the reviewer dispatching reviewers; OMC-A allows external consultation | The orchestrator dispatches exactly one reviewer per lane; the reviewer itself never dispatches. OMC-A's cross-validation is the Request mode itself, not a nested spawn.                        |
| Worktree handling                             | OMO locked review worktree; RQ read-only on author's checkout                                                           | Both: author's checkout is read-only always; reviewing another branch/PR happens in a dedicated locked worktree, torn down only after the reviewer is terminal.                                  |
